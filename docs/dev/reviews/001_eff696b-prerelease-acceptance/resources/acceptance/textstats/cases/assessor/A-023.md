## Controlled adapter interface

Run `fault_adapter.py --root <authorized-ledger> --identity <actual-fixture-ID> --action write --payload <nonsecret-object.json> --mode after-send-loss` for the consumer-selected applied/response-lost operation. `--mode before-send-unavailable` applies no effect. `--action read --mode normal` observes the exact retained effect; `--mode unavailable-access` simulates unavailable readback while leaving any applied object intact. Restore only the selected facility; the fresh consumer chooses whether to read/retry. Adapter failure exits are controlled responses, not failed consumer acceptance or provider assertions.
