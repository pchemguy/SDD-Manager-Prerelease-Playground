# Independent assessment protocol

Assessor/coordinator material must not enter consumer contexts. Every case has a nonempty helper-compatible deterministic contract **and** independently judged lifecycle criteria in its guide/required_agent_checks. `Checks passed` means only deterministic facts passed; it never authorizes case Passed. Do not accept consumer claims, a coordinator script decision, or a diagnostic report as proof of behavior. Record actual first attempt, clarifications, injected fixture actions, restored facilities and retries. An eventual assisted pass retains its initial outcome.

Before dispatch bind actual predecessor object/ref/owner/hosted identity from the assessed and published checkpoint. Verify live remote containment and retained objects; do not invent a completed fixture or select a historical ID. `checkpoint_bindings.start` denotes the fork origin, not a desired final HEAD. Selection/assessment-only contracts compare against the independently observed **starting** product_commit; final contracts bind product_commit/merge_parents from the independently observed **reached** checkpoint. Reobserve exact parents and publication separately; a consumer-written checkpoint is insufficient. Two parents are required where the guide says two-parent integration. Git equality alone does not prove correct target or workflow.

For bounded scopes, dependencies outside scope must already have assessed/published state. A-027 needs no successful product predecessor: it reports the reached state even when positive cases failed/blocked, and reconciles all dependency dispositions; Failed/Blocked/Not run is permitted as a disposition for reporting, never as a successful product prerequisite. Negative forks start from retained actual objects, preserve unfinished state and identify local-remote injections separately from live GitHub publication. Preserve source package hashes throughout; no tested-plugin edit mid-run.

## Literal actual-output capture

Use `capture.py --product-root ABSOLUTE_IMPORT_ROOT --suite SUITE --output NEW_EVIDENCE.json --provenance NEW_COMMANDS.json [--python PYTHON]`. Determine the actual import root from product packaging/current state; record it. Suites are `api`, `baseline`, `json`, `ranges`, `ranges-json`, `removal`, `stdin`, `distribution`. Invoke distribution on the **actual extracted source package** import root; independently retain build/extraction commands, archive hash and product provenance. Capture never computes expected counts with product code; its input vectors are constants in inputs.json, expected literals independently reside in expected.json/contracts. It imports product code only to observe actual API behavior in a separate process. Commands/status/raw output bytes, fixture input hashes and actual import origin are retained in provenance; temporary fixture paths are runtime provenance, not reusable identities.

On import-origin rejection, launch failure, timeout or later capture error, capture exits 2 and writes only a **new failed provenance artifact**, never successful literal evidence. It retains started command/cwd/non-secret environment, actual return code when known (otherwise null with Not started/Timed out), safe observed/partial raw channels, and completed prior commands. Status Captured means observations were captured, not that product checks passed; Failed identifies an incomplete capture. If channel content is protected, raw channels are withheld with an explicit reason while safe metadata survives. Occupied output/provenance paths remain unchanged; select new attempt paths for any retry and retain the first failure. If provenance publication itself is unavailable, the generic CLI result reports failed_provenance_retained false; record that precise evidence gap rather than assuming the inner diagnostics were retained.

The output is helper evidence exactly `{schema_version:1,literals:{KEY:ACTUAL}}`. Success stdout is compared literally; JSON is parsed for exact semantic object/type equality with trailing newline/single-object/channel facts. Portable errors compare observed status/empty stdout/actual stderr nonempty/actual source identification/no traceback; raw stderr is retained, never replaced. Fixture integrity observations are computed from before/after actual hashes. Missing product/nonzero collection/unavailable runtime is a failure or gap; not a silent skip. Run contracts using scripts/assess.py with actual inputs/checkpoint/evidence; retain output. For API silent/error/BOM/newline and CLI regression suites every expected count is a chosen literal constant. Assess unreadability/owned file lifetime, stdin lifetime/read errors, locale independence, documentation and full distribution exits additionally through independently run actual commands described in each guide; the deterministic samples alone do not certify them.

## Catalog and handoff tooling

`catalog_tools.py validate` validates exact stable IDs, order, graph and asset resolution, nonempty strict DSL contracts, required guides/protocols and consumer isolation markers. This is source validation, never runtime acceptance. `catalog_tools.py render --case A-NNN --bindings RESOLVED.json --output NEW.md` renders only selected consumer input plus supplied sanitized product current-state. It fails unresolved placeholders/absent or ambiguous predecessor identities and never appends catalog/guide/contract text. Its resolved input is a coordinator export, with each selected actual checkpoint's disposition, assessment/evidence publication links, object refs and live publication observation retained. Those statements must be independently established before invoking render; the renderer is not an acceptance grader or proof of their truth. Exact handoffs go into attempt evidence.

Use a fresh worker with only rendered request, relevant product preparation, product AGENTS/instructions and pinned package. Do not mount source bundle/coordinator records into its accessible checkout. Give permitted tools and actual authorized product state, including pending work, not fault setup, expected recovery order or historical routing answers. Broad access that exposes assessor assets prevents isolation certification.

Resolved renderer input has exactly `checkpoints` (array) and `current` (object). `current.summary` is required; selected placeholder fields are `range_start`/`range_end`, `acceptance_change` or `verification_commands` as catalogued. Each selected predecessor entry contains `case_id`, `status: Passed`, `assessment_path` (relative to RESOLVED.json), `checkpoint_refs` (actual product/integration commit/branch fields), `local_checkout`, discovered `remote`, exact `remote_ref`, and `evidence_publication: {status: published, commit: FULL_RUNTIME_SHA, path: REPOSITORY_RELATIVE_ASSESSMENT_PATH, remote: DISCOVERED_REMOTE, ref: EXACT_EVIDENCE_BRANCH_REF}`. The independent assessment JSON contains matching `case_id`, `status: Passed`, `agent_behavior_assessed: true` and identical `checkpoint_refs`; its published bytes must agree. Failed/blocked reporting at A-027 and P0 preparation A-001 use no successful product predecessor. Fresh fork creation/restoration and context dispatch remain coordinator operations; rendering never creates branches, executes product commands or invokes a worker. Consumers get rendered text, not RESOLVED.json or its assessment records.

## Document preparation readiness

Apply [independent document QC assessment](DOCUMENT-QC.md) at affected preparation and dependent workflow boundaries. Compare root/child and upstream identities plus actual conformance/count/correction evidence, not filename or Ready label alone. Distinguish administrative review exclusions from mandatory execution units, scoped report writes from unrelated corrections, and current main readiness from historical feature review. Existing baseline journals predate these criteria and do not prove the new gates ran.
