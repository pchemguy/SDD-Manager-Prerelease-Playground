# TextStats product request

Prepare a small Python text statistics utility through design, specification, plan and executable task hierarchy. Produce ordinary product artifacts in this repository and derive identities from its actual conventions/current state. Stop before implementing production code.

Use Python 3.11+, the standard library and unittest. Export immutable `TextStats(lines: int, words: int)` with nonnegative values, `count_text(text: str, *, strip_bom: bool = True)` and `count_file(path: str | os.PathLike[str], *, strip_bom: bool = True)` directly from importable `textstats`. CLI entry is `python -m textstats`. Organize discoverable nonempty product tests under `tests/unit/` and `tests/integration/`; put workflow fixture checks separately under `tests/workflows/`. Include public API/module documentation, a runnable README and a distribution check invoking the extracted source package's module entry.

Count CRLF as one terminator and lone CR/LF as terminators. Every terminator contributes a line; a nonempty final unterminated segment contributes one. Empty input has zero lines; a trailing terminator adds no phantom line. Other Unicode separators do not terminate lines. Words use Python str.split Unicode whitespace semantics. Remove exactly one leading U+FEFF by default; preserve interior BOMs and all BOMs with strip_bom=False/--keep-bom. Retained BOM is ordinary non-whitespace. API calls are silent. Decode files as strict UTF-8, raise OSError subclasses for missing/unreadable files and UnicodeDecodeError for bad bytes, emit no partial result and close owned handles.

Phase 1 milestone 1.1 supplies useful named-file counting/API/CLI. Baseline CLI is `python -m textstats [--keep-bom] INPUT`, with exactly one input and `--` support for dash-prefixed filenames. Success status is 0 and stdout exactly `lines=<N> words=<N>\n`, with empty stderr. Help exits 0. Phase 1 milestone 1.2 supplies failure handling, documentation/README and distribution exits. Input/read/decode failures exit 1 with useful identifying stderr, empty stdout and no traceback. Missing/extra input or unknown options exit 2 with useful stderr, empty stdout and no traceback. Inputs remain unchanged.

Phase 2 milestone 2.1 adds --json: one object plus newline, integer lines and words only, same counts; key order/spacing are free. Preserve text default. Milestone 2.2 later adds stdin through `-`: read bytes until EOF, decode UTF-8 independent of locale, never close stdin; empty stdin is (0,0); read/decode errors exit 1 identifying stdin. Final exits cover docs/distribution and retained behavior. Do not implement phase 2 during this preparation request.

A later separately requested range feature adds one --lines START:END or --lines=START:END. Positive ASCII decimal, inclusive one-based endpoints, START <= END; leading zeros are decimal. Reject signs, whitespace, Unicode digits, zero, reversal, open endpoints, extra colons and missing/repeated range options with usage status 2 before acquiring input. No arbitrary endpoint limit. Decode complete input before selecting (bad bytes after END fail). Apply BOM policy once before numbering; preserve selected contents and terminators; beyond EOF selects available subset or zero. Exposing an interior BOM must not strip it. Options compose in either order. Public API stays whole-input with no new range parameter/export. Named-file text/JSON range behavior is the feature's delivery boundary. Source-independent compatibility with future stdin is a design constraint; stdin acquisition/delivery remains the later milestone.

Sample semantics: empty=(0,0); alpha beta=(1,2); alpha followed by LF=(1,1); LF=(1,0); alpha CRLF beta CR gamma LF=(3,3); alpha LF LF=(2,1); space/tab=(1,0); alpha U+2028 beta=(1,2). For `alpha beta\nbeta\nlast two`, 2:3 and 2:99 give (2,3), 1:1 gives (1,2), 4:99 gives (0,0). For `a\n\n`, 2:9 gives (1,0). For `a\r\nb c\rd\n`, 2:3 gives (2,3). BOM-only default gives (0,0), keep BOM gives (1,1). Two initial BOMs default give (1,1).
