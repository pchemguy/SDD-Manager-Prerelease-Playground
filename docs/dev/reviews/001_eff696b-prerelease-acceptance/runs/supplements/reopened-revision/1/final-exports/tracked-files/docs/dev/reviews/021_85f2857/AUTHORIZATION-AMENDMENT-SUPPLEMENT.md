## P004 extension — preserve native human authority across delegation

Affected paths: skills/sdd-manage/references/coordination.md, skills/sdd-manage/references/revision-authorization.md, skills/sdd-implement/references/completion-and-checkpoints.md, skills/sdd-forge/references/github-issue-lifecycle.md, acceptance/textstats/EXECUTION.md.

Observed trigger: a fresh worker receives exact current scope, destination, payload and retained human push authorization, but platform publication review treats that context as untrusted agent text. A012 preparation and implementation pushes were each rejected in the worker and accepted through the same ordinary Git operation after the primary session supplied actual retained human instructions, independently inspected payload/checks and exact effect readback. Original denials and assistance are retained in PUB006/PUB007. Prompt completeness alone did not establish native trusted-authority propagation.

Suggested instruction:

> Determine whether the runtime can carry the actual human authorization into a delegated operation through its supported trusted context. An ordinary agent prompt quoting the human is not proof that the platform received trusted authorization. When supported propagation is unavailable, keep prescribed publication with the primary execution context that retains the actual human request. The worker prepares its exact verified commit/ref, owned delta and results; the primary execution owner performs the ordinary scoped publication and returns verified destination readback before dependent work advances. This publication stage is part of execution; do not invoke a review skill or classify it as content review. After any denial, first preserve the operation/effects and supply materially new actual authority or evidence only through supported review/operation context. Primary execution is not an exemption: a remaining platform denial stays blocked, with no unchanged retry, alternate transport/account or dependent advance.

Keep the active implementation/steering workflow's ownership explicit even when the primary execution context performs its publication operation. Do not treat token possession as arbitrary scope or substitute credentials for the actual human request.

Regression: native trusted user scope available in primary but absent in a fresh delegated operation; actual exact denied effect remains absent; supported context reassessment either permits that same bounded effect and readback or retains a final blocker. Verify that no worker begins new implementation, hosted completion or integration while its required publication is pending. Repeat against a newly pinned source; do not retroactively pass the current worker denial.

## P001 enforcement — policy before every role's authority decision

Add the mandatory read to direct entry paths and fresh handoffs, including independent assessors when they react to a platform authorization rejection. An assessor read the policy after a reassessment in the earlier A010 context; the continuation read it first. A link in a coordinator table did not enforce the required order across contexts. Capture role/path/hash and ordering through observable native results; do not use a new mutable authority registry.

Regression: first direct implementation, hosting and assessor authority decision each follows actual policy loading. A missing policy read is a process failure even if publication later succeeds.

## Execution checkpoint discipline

Affected paths: skills/sdd-implement/references/completion-and-checkpoints.md, skills/sdd-steer references for staged amendment execution, acceptance/textstats/EXECUTION.md.

Reinforce the existing push-before-dependent-work gate: after a rejected preparation/completion push, retain pending work and stop dependent writes until exact publication is established. A012 began two test-first edits before the hold arrived; those edits were preserved, excluded from the preparation payload, and no production edit occurred before supported publication recovery. Record this as a consumer/process defect rather than deleting it or calling the denial harmless.

Retain full native command results, session IDs and completion status in the acceptance harness. Lost native handles and output-only orchestration cannot establish a command's result. This is harness evidence discipline, not a new product transaction protocol.
