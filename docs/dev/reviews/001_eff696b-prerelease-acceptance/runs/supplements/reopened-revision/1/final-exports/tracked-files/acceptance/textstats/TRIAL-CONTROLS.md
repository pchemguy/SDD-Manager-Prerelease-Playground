# Eligible fixtures and observed interruption controls

Before dispatch, validate the actual source commit, complete outside prerequisites, eligible phase/feature boundary, permitted destination and required facilities. Derive the full relevant phase task set from accepted owners, not a convenient checked subset. `scripts/trial_control.py --root <isolated-checkout> --check-document <relative-TASKS-path> --tasks <actual IDs...>` reads clean committed named task rows. It does not certify phase reviews, report/hosted closure or publication; independently verify those exits and exact refs as well. An incomplete/missing/uncommitted task owner is an explicit setup error before consumer work.

Catalog facilities are classified by requirement: missing required setup is Blocked; missing optional native/live setup is Not run/non-blocking. Record the missing facility rather than calling it a product failure. A-023 live response loss needs legitimate isolated hosted identities and post-write response suppression; A-024 native recovery needs supported protected handoff and recoverable native credentials.

For a cooperative fixture hold, `trial_control.py --root <isolated-checkout> --manifest <nonsecret-operation-manifest> --receipt <owned-gate-record> --hold-after <count>` runs the authorized actor's explicit argv operations and returns after actual partial state changes. The manifest has `actions` (argv lists), `watched` (nonsecret product paths), and optional `pending_paths` (selected transfer paths that must still match their initial state at the hold). The receipt remains outside the watched product files. Its lexical path and parents must not be symlinks; validate them before resolving the destination for both fresh execution and resume. Hold count must precede remaining operations. No actual change, or an already-changed pending transfer, rejects the trigger. The gate retains HEAD/index/merge and selected file hashes/modes plus sanitized command results.

This is a caller-owned control around commands the consumer actually selected and performed. Never supply fixture-authored task completion or transfer edits and describe them as consumer behavior. The independent assessor must establish the actor, selected incomplete transfer, ordinary authorization and fresh continuation. A helper's Held result alone is not agent acceptance. For A-021, choose observed selected transfer operations and pending paths, not a report-QC update that does not change transfer state.

A separate fresh authorized consumer can continue a Held manifest with `--resume`, using the same command identity and exact retained snapshot. Changes outside the hold, different commands, failed/uncertain operations and completed receipts reject automatic continuation. Reconcile actual state and retain the original evidence before selecting a supported recovery. Unknown operations are never silently replayed. Receipts are atomically replaced; historical attempts belong in separate receipt paths.

Native process termination remains a separately labelled optional extension when unavailable. Cooperative gate execution does not prove native kill, process isolation or cross-machine reconstruction. Actual stdout/stderr containing protected content is withheld; do not put credentials into manifests, receipts or handoffs.
